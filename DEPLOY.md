# Deploying your portfolio

Plain static HTML + CSS. No build step, no dependencies, no framework. That means it deploys anywhere and will never break because a package updated.

---

## Step 1 — Preview it locally (5 seconds)

**Double-click `index.html`.** That's it. Every path in the site is relative, so it works straight off the filesystem — no server needed.

If you'd rather preview it exactly as Vercel will serve it, run this from *inside* the `Portfolio` folder (note the `cd` — running it from `Growth` serves the wrong directory):

```bash
cd C:\Users\ahraz\OneDrive\Desktop\Growth\Portfolio
python -m http.server 5500
```

Then open `http://localhost:5500` yourself — the command doesn't launch a browser. If the page looks wrong, an older server is probably still holding the port: close every cmd window and try a different port number.

The form is wired but not connected yet. It's currently a placeholder — if someone submits, they'll see a message telling them to email you directly.

*Prefer to skip it?* Delete the `<form>` block — your email, phone and LinkedIn are already listed right next to it.

## Step 2b — Turn on recommendations (10 minutes)

The recommendations section already works visually. To make submissions actually save and publish, you need a free Supabase project. No card, no expiry.

### 1. Create the project

Go to **[supabase.com](https://supabase.com)** → sign up → **New project**. Pick any name and region (Mumbai is closest). Wait ~2 minutes for it to provision.

### 2. Create the table

Left sidebar → **SQL Editor** → **New query** → paste this and hit Run:

```sql
create table recommendations (
  id          bigint generated by default as identity primary key,
  created_at  timestamptz default now(),
  name        text not null check (char_length(name) between 1 and 80),
  role        text not null check (char_length(role) between 1 and 120),
  message     text not null check (char_length(message) between 10 and 1200),
  approved    boolean default false
);

alter table recommendations enable row level security;

-- anyone may submit, but only ever as unapproved
create policy "anyone can submit"
  on recommendations for insert
  to anon
  with check (approved = false);

-- the public only ever sees what you've approved
create policy "public reads approved only"
  on recommendations for select
  to anon
  using (approved = true);
```

That second policy is the important one. Without it, a submission would appear on your site the instant someone hit send.

### 3. Copy your keys

Left sidebar → **Project Settings → API**. Copy:

- **Project URL** — looks like `https://abcdefgh.supabase.co`
- **anon public** key — a long string starting `eyJ...`

Paste both into `config.js` in the portfolio folder, replacing the placeholders.

> **Is it safe to commit the anon key?** Yes. It's designed to be public — it only grants what your RLS policies above allow, which is "insert an unapproved row" and "read approved rows". Nothing else. Never put the `service_role` key in this file.

### 4. Approving a recommendation

When someone submits, you'll see the row in Supabase under **Table Editor → recommendations** with `approved` set to `false`. Read it, and if you're happy, tick the `approved` checkbox. It appears on your site on the next page load.

Want an email when one arrives? **Database → Webhooks** can ping you, or just check the table now and then.

### 5. Seeding it with existing recommendations

If you already have LinkedIn recommendations, add them directly in the Table Editor with `approved` set to `true` — or, if you'd rather not use Supabase at all, paste them into `SEED_RECOMMENDATIONS` in `config.js`:

```js
window.SEED_RECOMMENDATIONS = [
  { name: "Priya Sharma", role: "Engineering Manager, Vecmocon", message: "…" }
];
```

Those show whenever Supabase isn't configured or is unreachable, so they double as a safety net.

## Step 3 — Push to GitHub

Vercel deploys from a Git repo. If you don't have one yet:

1. Create a new **public** repo on GitHub called `portfolio` (public also doubles as proof you build).
2. From inside the `Portfolio` folder:

```bash
git init
git add .
git commit -m "Portfolio v1"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/portfolio.git
git push -u origin main
```

**Don't want to use Git?** Skip to Step 4b.

---

## Step 4a — Deploy on Vercel (recommended)

1. Go to **[vercel.com](https://vercel.com)** → **Sign up with GitHub**.
2. **Add New → Project** → import your `portfolio` repo.
3. Framework preset: **Other**. Leave build command and output directory **empty** — it's static HTML.
4. Click **Deploy**. It's live in about 20 seconds.
5. **Settings → Domains** → rename the subdomain to something clean, e.g. `ahraz-shamim.vercel.app`.

Every `git push` from now on redeploys automatically.

## Step 4b — Deploy without Git (drag and drop)

Install the CLI and deploy the folder directly:

```bash
npm i -g vercel
cd Portfolio
vercel --prod
```

Follow the prompts. No repo required.

## Step 5 — Update the URLs

Once you know your final domain, do a find-and-replace for `ahraz-shamim.vercel.app` across:

- `sitemap.xml`
- `robots.txt`

Then push again.

## Is Vercel actually free forever?

Yes, for this. The **Hobby** plan has no time limit and no credit card requirement:

| | Hobby (free) | What you'll use |
|---|---|---|
| Bandwidth | 100 GB/month | A few hundred MB at most |
| Projects | 200 | 1 |
| Deployments | 100/day | A handful |
| SSL / HTTPS | Included | ✓ |
| Custom domain | Supported (you buy the domain) | Optional |

Two things worth knowing:

- Vercel's terms describe Hobby as **personal, non-commercial**. A personal portfolio qualifies; selling services through it doesn't.
- If you somehow blow past the limits, Vercel takes the site offline until the cycle resets rather than charging you. No surprise bills.

### Alternatives (all genuinely free forever)

- **Cloudflare Pages** — *unlimited* bandwidth, unlimited sites, commercial use allowed. The most generous free tier available. Same drag-and-drop or Git flow. Worth switching to if you ever want to use the site commercially.
- **GitHub Pages** — the simplest option. Push to a repo named `YOUR_USERNAME.github.io` and it's live at that URL. 100 GB/month soft limit. No config needed for plain HTML.
- **Netlify** — 100 GB/month, drag-and-drop deploy, similar to Vercel.

All four host this folder as-is with no changes.

## Editing later

| Want to change | File |
|---|---|
| Hero text, metrics, about, experience, skills | `index.html` |
| Colours, fonts, spacing | `styles.css` (all colours are CSS variables at the top) |
| A case study | `projects/*.html` |
| Add a new case study | Copy any file in `projects/`, edit it, then add a card in the `#work` section of `index.html` |
| Your photo | Replace `assets/photo.png` |
| Your résumé | Replace `assets/Ahraz-Shamim-Resume.pdf` (keep the filename) |

To change the accent colour, edit `--accent` in `styles.css` — one line, whole site updates.

## Adding an image to a case study

Drop the file in `assets/img/`, then paste this block where you want it:

```html
<div class="fig fig-img zoomable reveal">
  <div class="fig-title">Your caption heading</div>
  <img src="../assets/img/your-file.png" alt="Describe it for screen readers" loading="lazy">
  <p class="fig-note">Optional note under the image.</p>
</div>
```

`zoomable` makes it click-to-enlarge in a lightbox. Drop that class if you don't want it.

## Changing the look

All colours live as CSS variables at the top of `styles.css`:

- `--accent` (`#2f5fff`) — the blue used across buttons, links and charts. Change this one line and the whole site follows.
- `--display` / `--sans` / `--mono` — Space Grotesk for headings, Inter for body, JetBrains Mono for labels. If you swap a font, update the Google Fonts `<link>` in each HTML `<head>` too.
- `--c1` … `--c6` — the data colours used in the infographic SVGs.

Animations respect `prefers-reduced-motion`, so they switch off automatically for users who've asked for that.
